测试用例:basic
我已经对所有basic指令进行了测试，其中出现了如下问题，我进行了修复：
1. clone测试时卡死，具体原因在于（generated by deepseek）
   clone.s 在 ecall 之前把 func 和 arg 存到了子进程栈上：

addi a1, a1, -16        # a1 = child_stack - 16
sd a0, 0(a1)            # 存 func
sd a3, 8(a1)            # 存 arg
ecall 之后，父进程和子进程都回到 clone.s 继续执行。子进程走这个分支：

1:  ld a1, 0(sp)        # 从 sp 位置读取 func
    ld a0, 8(sp)        # 读取 arg  
    jalr a1              # 跳转到 func
但你的 sys_clone → sys_fork() 只是简单 fork 了父进程，子进程的 sp 和父进程一样——等于父进程的调用栈指针，而不是 clone.s 里那个 child_stack - 16。所以 ld a1, 0(sp) 读到了垃圾数据，jalr 跳到非法地址，卡死或崩溃。

修复计划
改 os/src/syscall/process.rs 的 sys_clone，把当前的委托 sys_fork() 改成内联实现，多一步：stack 非零时，把子进程的 trap_cx.SP 设为 stack 值：
2. pipe 指令测试时卡死
   是因为测试用例写入的是int，而pipe指令用的是usize，字节长度不匹配
   我修复时又出现了多个问题，目前已经完全修复，更改了很多文件，现在rust pipe调用也适配 [u32; 2]
3. pipe 指令空指针
   测试用例直接调用wait发生了空指针，已经修复
4. sleep测试失败
   原因在于测试用例的C代码和我们写的rust代码要求的返回值不一样，我修复了sys_get_time，现在已经解决了
5. mkdir测试失败
   mkdir真不是人类修的：

   这是deepseek V4 pro分析的结果： ext4_rs 的 balloc 读取块组描述符的 free_blocks_count 字段——第一次调用读到 0，返回 ENOSPC。第一次失败过程中触发了 inode 分配和部分写入操作，让块设备的读写链路"预热"。第二次再读块组描述符就能读到正确的 24860。

   具体原因是：由于ext4_rs每次启动都会从磁盘重读块组描述符，这使得磁盘IO出现异步，EXT4不会优先看内存里的最新数据，如果读到旧数据就会出现问题。

   我目前的解决方案是，如果失败再调用一次即可，因为第一次做了预热，而mkdir失败在实际使用场景并不常见，所以不会太影响性能
   但是这个方法可能导致inode泄露或者生成2个文件夹，我需要思考这个问题。

openat 失败
根因：vfs_create 往 generic_open 传了 绝对路径（如 /mnt/test_openat.txt），但同时也传了 parent_inode = mnt的inode。generic_open 从 mnt inode 开始解析路径，第一个组件 "mnt" 在 /mnt/ 目录里找不到，就被当成了要创建的中间目录——最终文件创建在 /mnt/mnt/test_openat.txt 而不是 /mnt/test_openat.txt。

修复：vfs_create 只传 name（纯文件名）给 generic_open，不再组装绝对路径。generic_open 从正确的 parent_inode 出发直接创建 name。

mkdir_ 失败
根因：generic_open(create=true, S_IFDIR) 第一次调用必定返回 ENOSPC（块分配器读到错误的 free_blocks_count=0），第二次才正常。文件创建（S_IFREG）不受影响。

修复：vfs_create 里，目录创建（is_dir=true）失败时自动重试一次。第一次触发 ext4_rs 内部分配/写入预热块设备链路，第二次读到的 free_blocks_count 正确。

mount / umount 失败
根因：mount 表和路径解析用了 Arc::ptr_eq 做指针比较。mount 时 vfs_resolve_path 创建了一个 dentry 存入表；umount 时 vfs_resolve_path 通过 lookup_mount 重定向返回了挂载根 dentry（不是原始的那个），两个 Arc 指针不同，匹配失败。

修复：全部改用 path 字符串比较。vfs_mount 的重复检查改比较 m.mnt_point.path == path，sys_umount2 直接在 mount 表里按 path 查找条目删除，不再经 vfs_umount。
